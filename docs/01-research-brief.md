# 研究目标与边界

## 1. 问题定义

桥牌叫牌既是搭档之间的信息传递，也是双方争夺定约的竞争。本项目搜索搭档协议：双方如何根据自己的牌、公开叫牌历史和共同约定，选择叫品并解释搭档的叫品。

希望回答：给定明确的比赛分制、打牌结果近似和对手分布，是否能通过自动实验，持续找到比已有版本成绩更高、且可完整描述的协议？

“摸高”指在指定实验条件下寻找更好的体系；不声称证明全局最优、博弈均衡或人类实战极限。

## 2. 已与用户确认的决定

| 项目 | 固定要求 |
| --- | --- |
| 优化目标 | 第一阶段只按成绩优化 |
| 复杂度 | 不惩罚规则条数、篇幅、记忆负担、例外或协议层数 |
| 表达能力 | 允许一切能明确形式化的手牌概念和协议，不限于 HCP 与套长 |
| 自然语言 | 说明本身足以重建相同策略，包括边界、优先级、兜底和随机规则 |
| 搭档一致性 | 修改含义时，同步修改理解与后续流程 |
| 后续精简 | 留到独立的第二阶段，不进入当前适应度 |

不能以“太复杂”“不像人类体系”“太难学”为由拒绝一个更高分的有效候选。

## 3. 有效性条件与成绩分开

候选必须满足：叫品合法、信息来源合法、协议可执行、自然语言描述完整、运行可复现。

有效候选之间只按实验规定的成绩排名。无效候选标记为 `invalid`，不得通过偷偷替换非法叫品、丢掉失败牌例等方式变成可比较成绩。运行失败和基础设施错误也不能计作零分。

任何有限程序原则上都可能被文字描述，因此“自然语言可描述”不是严格的计算能力上界。本项目采用可操作标准：全部决策机制明确记载；不依赖说明之外的隐藏权重、人工判断或未定义的“最佳选择”。不限制说明长度。

## 4. 可调整的工程默认值

- Python 包＋命令行；无需先做前端、服务、集群或神经网络训练。
- 可版本化的 JSON 规则 IR，解析、校验、执行、生成说明共用同一份定义。
- 纯函数式策略；初版确定性决策，后续可以返回明确定义的动作概率分布。
- DDS 预计算并缓存；适应度主要使用配对 IMP，而不是成约率。
- 外层先用规则变异和种群搜索；大模型提案为可选来源，未配置 API 时流程仍可运行。
- 第一条局部研究路径为无干扰的 1NT 后续叫牌，随后扩展到四人竞争。

这些默认值可由实现者依据实际环境调整，调整必须写入决策记录。变更已确认的研究目标则需要用户明确指示。

## 5. 两种实验模式

### `uncontested-1nt`

固定并公开 1NT 开叫前缀、开叫条件与对手始终 Pass 的约定；仅演化该前缀后的搭档协议。比较候选与基准在相同手牌上的定约结果。

这是局部合作实验，成绩只能支持相应局部结论。固定前缀必须与抽样条件一致，不能由候选自行选择哪些牌进入评测。

### `competitive-full`

四个位置都有完整叫牌策略。候选搭档对阵固定、公开版本的对手；两桌互换体系位置，保持各座位手牌、发牌人、局况不变。

早期可冻结其他分支，仅演化特定子协议；最终逐步开放开叫、应叫、竞争、加倍、满贯等全部结构。每次报告列出仍冻结的部分。

## 6. 预期产物

1. 可执行的桥牌叫牌和计分核心。
2. 可描述、可修改、可导出说明的体系格式。
3. 可复现的牌例集与 DDS 缓存。
4. 同牌评测、路径统计和完整对局日志。
5. 候选产生、筛选、晋级和历史归档闭环。
6. 可证伪的实验结论：某次修改，在什么条件和样本上，有何收益与不确定性。

## 7. 先不做

初版不要求真实打牌机器人、人工记忆难度优化、比赛体系准入审核、图形界面、大规模分布式训练或任意自然语言自动编译。自然语言说明先由规则 IR 生成；自由文本提案需落到 IR 并验证后才可执行。

## 8. 历史近期目标：E002（2026-11-03）

执行、记录和审计底座具备后，工作重心转向Agent驱动的体系改进闭环，不再以完善界面或修完全部传统体系分支作为进化的前置条件。

用户设定的新目标是：从当前CCBA/精确工程v5.5.3出发，在全新10000个基础牌族上分别显著优于这两个固定起点。采用“随机新牌评测—统计和问题聚类—Agent提案—候选校验—共同新牌复测—新牌确认晋级”的过程。按后续决定不预留任何测试池，每轮现场随机生成；10000副检测也在候选确定后才生成。完成数据可供后续分析，新结论须用新牌并处理重复检验，恢复则复用尚未完成的同一轮输入。

两条起始谱系、固定对手身份、显著性/实际提升门槛、输入权限、错误预算和停止条件，统一以[E002实现与协议](12-self-evolution.md)为准。首版`evolve`已接通，文中的具体数量及`0.20 IMP/副`强门槛是冻结配置，不是已有结果。E001的局部1NT路径保留为诊断与小规模试验选项，不再是唯一入口。

## 9. E003：自主研究与原创体系

用户进一步确认，目标不是只给旧规则打补丁，而是让研究Agent具备从空白可执行骨架创造整套协议的能力。E003用持续工具会话替代一次性JSON提案：允许整体重写开叫、应叫、竞争、控制、接力、公开状态和fallback，自主生成牌例、编写并运行测试、调试、讨论和多轮迭代，最终提交完整体系快照。

默认模型按用户选择改为`gpt-6-astra`，不自动降级；模型、资源上限、实际用量和研究记录持久化。研究Agent能看授权的历史完整牌，运行期牌手仍只看自己的牌和公开信息；裁判、评分、对手和未完成正式评测不向研究工具开放写入或预读。

空白起点指不继承固定人类约定，不是声称模型没有桥牌先验。研究中间版本可以退步或尚未完整；只有可执行、说明同源、测试和有效性门禁通过的完整候选才能参加可信比赛。成绩仍是唯一适应度，复杂度、创新程度和人工参考相似性都不加减分。能力及边界见[E003实现](12-self-evolution.md#17-e003自主研究agent)。

## 10. 当前近期重点：可验证研究吞吐（2026-11-05）

E005/E006已证明工具式研究者能实现完整协议，但尚不能稳定将已发布候选送到可信实验结论。近期按[Auto-Research计划](14-autoresearch-plan.md)先修上下文/结果边界和固定参考缺口，再解耦研究与评价、提供无模型评价、保留失败并记录单位有效结果成本；不直接扩大预算或研究Agent数量。

随后用有明确入口、出口和外围接口的1NT模块做Local vs Global多次受控Pilot，分别报告条件与总体IMP。模块合同约束一致性，不锁死传统叫品含义；1NT实验不取代从零演化整套体系的长期目标。类型通过、行为变化、回归通过、完整评价、独立晋级及万副目标分别陈述。
