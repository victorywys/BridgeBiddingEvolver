每个里程碑都交付能实际运行的产物、说明和对应检查。先跑通小规模可信闭环，再增加规模与表达能力。不要以搭出目录、返回假分数或打印一条“success”视为完成。

起步路线为M0–M4局部执行/评测，再进入M5。四人竞争、两桌评测及完整协议研究原型已经接通，但稳定的研究—评价闭环尚未完成。当前按[Auto-Research计划](14-autoresearch-plan.md)优先修可靠性与研究吞吐，不直接扩大运行。确定性变异/录制提案保留为对照和无模型测试来源。

## M1：叫牌状态与计分核心

交付牌/手牌验证、合法叫品、状态转移、终局定约、庄家识别、重复桥牌计分和带符号 IMP 换算。

必须覆盖：

- 开局四 Pass；有非 Pass 后的结束规则；Pass、X、XX 与新定约对状态的影响。
- 所有 35 个定约叫品的顺序；同阶换花色；7NT 边界。
- X 仅针对对方最近的未加倍定约；XX 仅针对对方加倍；经过 Pass 后仍需正确识别双方。
- 新定约重置加倍；不能对搭档定约加倍或错误再加倍。
- 庄家由最终一方最早叫出最终 strain 的人确定。例：N 1C，E P，S 1H，W P，N 4H，E P，S P，W P，庄家为 S。
- 满贯、超墩、加倍及再加倍罚分、局况、南北/东西视角。
- IMP 所有分段边界、0 差和负差，避免边界偏一。

计分固定案例，以下均为庄家方视角，需依据权威表再核验：

| 定约与结果 | 局况 | 得分 |
| --- | --- | --- |
| 4S 正好 | 无局 / 有局 | 420 / 620 |
| 3NT 正好 | 无局 / 有局 | 400 / 600 |
| 2H 超二 | 无局 / 有局 | 170 / 170 |
| 2H X 正好 | 无局 / 有局 | 470 / 670 |
| 4S X 宕三 | 无局 / 有局 | -500 / -800 |
| 4S XX 宕三 | 无局 / 有局 | -1000 / -1600 |
| 6NT 正好 | 无局 / 有局 | 990 / 1440 |
| 7NT 正好 | 无局 / 有局 | 1520 / 2220 |

关键性质：`signed_imp(-x) == -signed_imp(x)`；同一得分的 NS/EW 视角互为相反数；不合法状态转移显式失败。随机走合法动作应终止且所有动作合法；不得用过小的随意轮数上限截断合法长叫牌。

## M2：体系 IR 与可执行基准

交付 v1 schema、受限解释器、完整自然语言渲染、规则 trace 和确定性的初始 1NT 协议。

初始协议要明确开叫条件、应叫、再叫和退出；不要求起步很强。先完成本项目自己的清楚定义，不要宣称是完整 SAYC 或“标准体系”。

验收：

- 复杂特征可通过组合或注册算子扩展，而非写死 HCP/套长两种判断。
- 相同体系和观察产生相同动作；自然语言覆盖优先级、边界和兜底。
- 私牌/DDS 不进入观察；改变其他三手但保持自己的观察相同时，动作不变。
- 故意制造规则重叠、非法动作和未定义引用时明确失败。
- 正确重建协议上下文；多次运行和不同牌例之间无私有状态残留。

## M3：真实 DDS、数据与缓存

交付实际 DDS 适配器、固定牌例 fixtures、20 项表缓存、分组数据划分和版本清单。

验收：至少若干真实牌例与独立可信结果核对；逐项确认庄位、花色和墩数方向。缓存命中与重新求解完全一致。真实求解失败不写成成功缓存。相同牌的局况变体不需重复求墩数，但计分结果可能不同。

若机器上暂时不能接通 DDS，保存可用核心与明确安装诊断，继续不依赖真实 DDS 的工作；M3 的真实求解验收保持未完成。不要用 fixture 结果冒充接通。

## M4：首个可信评测

原起步路径是`uncontested-1nt`；目前已接通`competitive-full`两桌调度。M5可以在完整竞争环境中局部修改协议，明确仍冻结的分支；不需要再造计分或DDS，也不要求先修完所有传统约定。

验收（竞争相关项在后续竞争阶段完成）：

- 同一确定性体系与自身比较为 0。
- 交换 A/B 后，竞争模式逐牌 IMP 反号；两桌 dealer/vulnerability/四手牌相同。
- 同一 manifest 重放可复现；worker 数量变化不会改变确定性结果。
- 两桌合起来只算一个独立基础样本；相关变体按组处理。
- 在测试替身下验证计分管道，在真实 DDS 下完成至少一次小规模集成评测，并在报告中清楚区分。

## M5：首条可信进化闭环

按顺序交付：

1. **实验骨架**：两原始体系哈希、共同数据manifest、可信评测端、10000副分片执行与全局统计接口。
2. **分析与问题台账**：父子收益差、模块覆盖、问题聚类、代表/边界/正常牌，复用紧凑记录和单叫展开。
3. **提案与校验**：Agent分析并输出原子IR补丁；提供确定性提案对照，检查发送/含义/续叫和影响范围。
4. **筛选与晋级控制器**：共同牌分阶段复测、有限新牌确认、两个谱系冠军、错误预算、断点和原始锚点归档。
5. **达标检测与展示**：冻结一个候选，按E002协议现场随机10000副，分别对两个起点检验；无需预留测试集。

先跑[E002小闭环](12-self-evolution.md#15-运行方式与配置)：工程smoke为3代、每代最多4个候选、16/8/16/32/64副；pilot为128/128/200/1000/2000副，均不自动启动10000副。每个新阶段独立随机，同轮共享；无进步保留冠军，不强制升级。

验收：不靠人工逐个修改/提交候选即可完成多代；父子关系、完整IR、说明、假设、拒绝及未提升均可追溯；无效候选不进排名；待评测的新牌不被提案器预读；复杂度不进入成绩；预算、晋级指针和恢复状态真实持久。旧E002 `source=agent`有白名单限制，E003 `source=research`已允许完整v2编辑，自动模块合同仍待加强。跑通原型、可靠闭环与最终强目标分别验收。

## M6：结构进化与搜索范围扩展

E003已把M5的一次性局部提案升级为完整v2协议研究：规则/含义/优先级/公开状态/fallback都可重写，支持现有与空白起点；研究中间版本和未晋级分支可继续迭代，实际回归失败返回同一会话修复。默认GPT-6 Astra，模型和预算在启动前冻结并可由界面设置。

后续仍需增强：自动推导/生成更全面的边界语义合同、更多语言能力、历史对手联赛与适应型对手诊断。不是因为结构编辑已开放，就宣称已经找到完整最优体系。需要新算子时仍走独立语言扩展，不让研究Agent直接改可信引擎；密钥不写入manifest或日志。

模型不可直接修改适应度、测试集、DDS、计分或引擎。模型输出按数据解析，不作为命令执行。先在固定 IR 上产生 patch；需要新语法时明确登记扩展需求。

验收：至少一次联合修改发送/解释/后续的完整结构变异，通过可信校验和真实评测，允许结论为“无提升”。模型不可用时，M5的控制流程仍能以确定性/录制提案测试，不能返回伪造的模型分析或改进。
