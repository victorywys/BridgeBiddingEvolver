# E008：自然1NT模块的受控进化与资源记录

本阶段接续[可靠性修复](16-framework-reliability.md)，补齐最小模块合同和基础资源账，再启动小规模研究。不是恢复整套体系的大搜索，也不是已经完成Local vs Global论文实验。

## 1. 固定什么，开放什么

以[已发布Z体系](../systems/research-z/index.json)为源，从同一v2定义复制自然1NT后续闭包，建立`nt15.*`命名空间。只有自然1NT开叫转入隔离模块；原2NT、强开叫、竞争及其他分支继续使用原协议。

```bash
.venv/bin/bridge-evolve system build-nt-module \
  --system systems/research-z/7a68e80669e1488bbcdc910ec6a61d78b6648478da888fbe436158e01a0e67f5.json \
  --output systems/nt-module-new
```

当前研究锚点与合同在[nt-module-v1](../systems/nt-module-v1/)。复制不是新发现：原探针上的完整叫牌与源体系相同，新增明确的非逼叫Pass出口及标准公开账本，避免用全体系fallback掩盖漏答。

合同固定开叫范围15–17、4333/4432/5332、外围语义、原参数定义与出口。内部全部规则、公告、问答树和特征可变，可新增`nt15.*`状态/参数；规则ID不受旧约定白名单限制。

公共`nt15.active`仅作为模块生命周期标记：入口设True，显式外部退出必须清False，`otherwise`保持模块内部。外围规则在active期间不参与解释或决策，新增内部状态不会激活外围的自然叫品解释。不得借模块改动修改外围开叫或共享含义；扩大范围应另立实验，而不是永久限制语言能力。

## 2. 有限合同，不冒称全空间证明

固定42个诊断类别：7个点力档与6类手牌形状交叉，包含7/8/9/10点边界、双高花、五张高花、长低花及均型。各例包含完整52张牌、实际发牌人/局况；生成器未放宽条件，每个类别和发牌完整性都核对。

这些都是已消耗的诊断输入，不是保留测试集，也不构成独立强度成绩。已有例直接保存到研究工作区，`read_contract(view="cases")`返回可用`case_id`和`side`。

检查项：

- 同源v2类型检查、冻结外围语义和允许的内部/外部状态边界；
- 所有探针自然到达1NT，不把强行指定前缀当行为见证；
- 决策规则最高优先级无冲突、人工发叫与回答有合法后续；
- 模块行动不落到全体系fallback，公开点力/套长保证不虚报；
- 无干扰必须达到声明的完成出口；10点及以上应叫的接口要求完成至少成局，而不是全Pass；
- 另测`1NT X/2C/2D/2H/2S`五个干扰前缀的显式外部交接。它们标为反事实边界探针，不计自然覆盖或成绩。

“完成成局”是本Pilot的明确接口契约，不是声称所有体系、所有牌例都应如此，也不是额外适应度。缺陷注入验证漏答、重叠、错误保证和退出；允许替换至少两个耦合分支，不能把“能返回Pass”写成协议完整。

模块发布除实际执行作者回归外，必须有`mode=auction`、空`prefix`且`changed_from_parent=true`的完整自然叫牌见证。只写强制前缀的单手决策测试不够。模块合同在发布和可信评价端分别重跑，不能仅信历史“通过”数字。

## 3. 研究Agent操作

先`read_contract(view="interface")`，再按`nt15.*`状态或具体ID用`navigate_system`定位。`read_contract(view="cases",offset=...,limit=...)`返回已保存探针，不需要重新手写四手牌。

`run_contract`实际执行42个自然探针和干扰接口；失败返回具体来源。`edit_system`仍允许完整原子编辑，中间稿可不合法；发布前需修好所有问题。

使用既有`inspect_case`、`write_tests/run_tests`及小型DDS诊断，注意探针的`side`。诊断允许读取完整手牌/DDS，实际策略仍只收到本人手牌和公开信息。不要把一副双明手最优定约当作必须叫到的目标。

`inspect_case.turn`从1开始；不使用DDS时，`side`选择候选所在方，只有一张模拟桌，`table=1`可省略，`table=2`不合法。使用`dds=true`时始终计算两张换位桌，`table=1/2`分别选择候选坐NS/EW的桌；`side`也可用于选择相应桌，二者冲突会拒绝。传`turn`会返回实际选中步骤，不再忽略该参数。

研究工具发布明确的嵌套参数schema，执行时在发牌/叫牌/预算预留前递归校验。错误返回`pointer`，例如`/turn`或`/sampling/constraints/S/suit_lengths`；v2编译错误也带精确源路径，如`/rules/0/id`、`/rules/0/action/call`、`/protocol/states/nt15.nt/on`，不只返回“需要非空字符串”。

定制诊断发牌的合法示例：

```json
{
  "sampling": {
    "count": 4,
    "dealer": "N",
    "constraints": {
      "N": {"hcp": [15, 17]},
      "S": {"hcp": [0, 7], "D": [6, 7], "S": [0, 4], "H": [0, 4]}
    }
  },
  "seat": "N",
  "hand_condition": {"op": "balanced"}
}
```

花色区间直接位于各座位条件内，不套`suit_lengths`。这只保证给定手牌条件，不强制拍卖走某个前缀；仍需自然整副重放核对进入路径。

诊断包按实际模块状态筛选，不要求新规则沿用旧命名。有限样本没有碰到改动时如实记录，不凭规则数、说明篇幅或新颖性奖励/惩罚候选。

### 定制发牌与评价的接线边界

E008运行时两条路径尚未连通：

```text
generate_cases(定制条件) → 工作区cases → inspect_case / 作者回归 → 诊断证据
trial / 发布后队列 → Evaluator生成新均匀牌 → 双桌DDS计分 → Global开发反馈
```

E008确实生成4副弱长方块诊断牌并用于回归；这不意味着随后的64副探索或256副full包含这些条件。原评价器不读取工作区cases，也不接收sampling参数。低频分支在均匀牌中可能零匹配，因此`insufficient_coverage`不表明定制生成器失效。

2026-11-06：已接通`development_sampling`批量条件开发评价。抽样条件在新实验初始化时冻结；`trial`和发布后队列都调用原发牌器，在这些条件下现场生成共同新牌，不读取设计时的案例库。每副检查完整52张牌、手牌谓词、局况/庄位、独立牌族和抽样身份；恢复复用原manifest，不重抽、不重复计费，条件变化属于新评价身份。

局部研究按“合同/回归 → 条件成绩与不确定性 → 模块集成 → 体系定稿后全局验收”进行，不要求每个局部候选先在均匀全局牌上证明显著。回归验证正确性；条件评价测局部收益，不是单元测试通过数。全局兼容性回归仍保留，不把条件收益写成全局提升。

新配置的`development_sampling`含名称、直接N/E/S/W区间、`hand_conditions`布尔手牌表达式、发牌人/局况和尝试上限；不接受候选规则命中、历史或未冻结的策略特征作抽样条件。各阶段的`boards`仍规定确切数量，`full`在此表示完整的条件开发轮次，不表示全局分布。执行器仍是相同四人竞争、固定对手、真实DDS和两桌换位；这里不是强制前缀或对手Pass的合作评分。

条件配置要求`allow_promotion=false`与`automatic_goal_check=false`，单次阶段目前至多1000副。万副全局验收必须另立冻结的均匀实验。队列记录配对父本差、95%牌族bootstrap区间与实际行为变化比例；采样失败保留，不放宽条件或补牌。

[E009无模型复评配置](../experiments/e009-conditional-minor-evaluation.json)迁移E008冻结的弱长低花候选，在预先声明的1NT开叫人和弱长低花应叫条件下，运行8/16/128副共同新牌。E008原配置、随机牌、分数与模型用量不改；没有复用4副诊断牌，也不申请晋级。

## 4. 基础资源账

每次模型请求登记实际输入/输出、缓存读写、未缓存输入及上游`total_nano_aiu`收据。AI Credits为该整数除以`1e9`，不是用总token乘固定费率，也不读取账户余额。缺少或异常收据明确未知，不补0。

原始失败/重试预留仍保留，模型错误也计请求；缓存多不等于研究有效。报告包括：

- 运行与会话的请求、实际/未知token、AI Credits、完成等待时间；
- 非模型工具时间与含模型的consult时间分列，不重复相加；
- 每轮实际计算/缓存配对、DDS缓存命中/新求解/新鲜核对；重用完整配对缓存时不把旧DDS计数再算一次；
- 不同候选、发布次数、已评价/可评分数量与比例；
- 每个已评价候选的本轮研究成本。分母为0或收据缺失时返回不可定义，未产出候选的研究也计入总成本。

发布物附会话累计资源快照，评价任务保存各阶段计算记录。共享研究成本不能把多个累计发布快照简单相加。

`resources.json`在运行报告中保存；看板可展开资源表，或读取`GET /api/evolutions/<id>/resources`。老运行未登记的收据不伪造，默认接口不扫描全部模型响应做昂贵回填。

## 5. 本轮规模与结论边界

[E008配置](../experiments/e008-controlled-nt-pilot.json)：

- 一个研究谱系，最多5个会话/代，每会话24轮，最多发布1个不同完整候选；
- GPT-6 Astra/high，最多160次共享请求、200万统计token、2小时；
- 2个评测worker，不是2个研究Agent；12000个配对硬上限；
- 每候选32/64/256副新牌作validity/screen/full，并独立预留600秒；
- **不申请晋级，不自动运行10000副**。失败或无提升完整保留，不为凑5个而强迫交付无效改动。

```bash
.venv/bin/bridge-evolve evolve run \
  --config experiments/e008-controlled-nt-pilot.json
```

比赛仍复用统一的通用四人引擎、v5.5.5固定对手、真实DDS、两桌换位和配对IMP。每阶段候选冻结后现场抽共同新牌，恢复复用原输入。

E008的full成绩是均匀完整发牌下的Global开发反馈。探针的“通过率”不是Conditional IMP，按模块状态筛诊断也不是独立条件强度测试。目前已分开支持冻结条件的批量开发计分与均匀全局计分；同预算、多次独立研究的Local vs Global方法对照仍未完成，不用单条轨迹作方法优越性或最强体系主张。

## 6. E009实际条件复评

[E009结果](http://127.0.0.1:8765/?evolution=evo-5a75a24f03b24bfe8fdfd61e6a0be2ba)迁移E008唯一冻结发布物，未再次调用研究模型，也未改原实验。8/16/128三个阶段共152个新牌族，与此前诊断/评价牌族没有重叠。

- 最后128副条件牌中，新弱低花发送规则实际命中113个牌族，改变113副完整叫牌；
- 相对父本的条件配对收益为`+1.25 IMP/副`，95%牌族bootstrap区间为`[+0.51171875,+1.9921875]`；
- 作者16项回归与冻结模块合同通过，全部评价牌保留，没有删除失败牌或以零分替换；
- 新增模型请求0，累计配对预算608单位；首次脚本入口不支持spawn，通过正式CLI恢复同一实验、同一输入，旧日志保留且预留未重复收费。

这说明弱长低花局部改动在本次冻结条件开发样本中相对父本有正向证据。候选对两个固定参考的条件平均成绩仍为`-0.421875 IMP/副`，不代表已经胜过参考体系；更不代表全局提升、独立晋级或方法论文结论。全局大样本验收留到模块集成/体系确定后的独立阶段。

## 7. E010继续研究与扩大的研究单元

[E010配置](../experiments/e010-continued-nt-research.json)保留E008工作区，使用其已发布且经E009条件验证的版本作为[新的开发亲本](../systems/nt-module-v2/anchor.json)。它不是全局晋级；旧锚点与原费用、失败和成绩仍在原运行保存。

`research_seed_parent=origin`显式保留新配置的开发亲本，不自动退回来源运行的旧亲本。来源草稿必须与该亲本语义一致；旧回归断言和案例保留，旧变化见证转为亲本回归，旧测试/探索结果归档到`prior_parent_evidence`，新发布必须有相对当前亲本的真实变化。

两个研究单元各最多80回合；24/48/64回合只是保存上下文的软进度检查点，不拆成新代。检查点提示剩余预算、当前测试是否有效和下一步；请求大小超限仍按原有界机制压缩。测试的`document_hash`对应实际验证的原始工作稿，避免正规化默认字段造成“刚测过却仍显示过期”。

本次新增预算为200个共享模型请求、800万统计token、4小时、20000个配对单位；每单元至多两次发布、320副诊断牌和1小时，候选评价预留15分钟。上下文250KB、输出16384token及结果有界限制不扩大，旧消耗不清零或重标成本。

继续E008最后查阅的高花方向，条件牌固定为N自然15–17均型1NT、S至少四张高花，研究转移/Stayman与邀请成局的耦合后续。没有使用弱长低花条件评高花设计，也不申请全局晋级或万副测试。实际配置和运行身份独立冻结，后续恢复通过正式CLI重放原输入。
