# 研究反馈、修订参考与独立候选评价

这次实现[近期计划](14-autoresearch-plan.md)的三项基础修复：有界反馈、两处已知参考缺口、研究与候选评价解耦。不增加研究Agent、不扩大模型预算，不实现后续1NT方法对照或campaign级统计控制。

## 1. 有界反馈与可追溯完整证据

模型默认读取摘要，而不是完整错误字符串、全部历史规则或巨大的旧测试结果。

- 断言失败保留失败状态、测试名、断言路径、短实际/预期预览，以及`details_ref`。
- 完整实际/预期值存为按内容哈希命名的不可变JSON，登记路径、SHA-256与字节数。恢复或迁移核对文件与内容身份。
- `read_result(result_id=...,pointer=...)`读取批准的结果；集合分页，长字符串支持`text_offset/text_limit`。不接受主机路径。
- 普通工具结果、consult、启动继承、自动handoff和展示摘要统一限长。最终校验的是完整模型请求，包括工具定义。
- 跨代、跨实验承接摘要时一并迁移其引用的完整证据。旧33MB失败记录不删、不改成通过，不把截短预览冒充完整原值。

原始`read_system`和同源完整规范仍保留。限制的是传输视图，不是体系复杂度或研究权限。研究者可以按引用和稳定节点展开所需部分。

展示接口默认返回有界内容；“下载完整证据”是显式请求：

```text
GET /api/evolutions/<id>/research/<session>/evidence?pointer=/last_tests
GET /api/evolutions/<id>/research/<session>/results/<result_id>
```

后者也支持队列回归的`eval-q-...`会话。两种接口都核对批准的实验/文件身份及可见性，不跟随任意文件路径。原“完整工具输入输出”查看改为摘要，完整JSON通过下载访问。

## 3. 持久评价意图与独立资源

发布完整候选后立即登记`evaluation_queue`，不等其他谱系或本代结束。当前用单可信控制器在安全边界优先排空队列，不增加并发研究模型。

每项意图冻结：

- 候选/父本、引擎、固定对手、评分口径、开发阶段规模和回归合同；
- 发布来源列表；同哈希、同合同的重发共用任务；
- 配对和时间预留、阶段与输入清单、回归/比赛结果及明确的终止原因。

变更回归合同是不同评价意图，但不会增加“不同候选”数量。每个任务冻结候选与父本后才抽共同新牌，后来的意图另开批次；不按不同批次的原始均值混排。

开发阶段为`validity -> screen -> full`，每阶段候选与父本使用同样的两个固定对手和牌例。最坏配对预留为：

```text
2个策略 × 固定对手数 × (validity副数 + screen副数 + full副数)
```

未使用配对在任务结束后释放。研究诊断不能占用已经预留的评价额度；模型请求超时窗口也不能消耗该预留时间。正在执行的原生DDS在安全边界停止，不粗暴杀死库调用。

SQLite以稳定配对键持久记录计费/预留：中断后缺失的计算可重做，但同一键不重复占用配对额度。已经完成的输入、摘要、日志和缓存都核对哈希，不换牌、不补0分。硬退出留下的未知活动时间按持久时间租约保守计入；正常安全停止则保存准确剩余额度。

模型在后续请求失败时，已承诺的评价仍在其独立硬预算内处理；总时间用尽、取消或可信源码改变时明确停止并保留任务，不声称资源无限或结果已经完成。

## 4. 无模型评价

使用[工程验证配置](../experiments/e007-framework-evaluation.json)，从Git发布索引恢复两个不同Z候选：

```bash
.venv/bin/bridge-evolve evolve evaluate \
  --config experiments/e007-framework-evaluation.json
```

也可在新配置中指定`evaluation_sources`，或增加：

```text
--from-releases evo-<停止的运行ID>
--from-releases systems/research-z/index.json
```

仅复制冻结协议、原始回归与来源，不复制旧分数、冠军晋级结论或清零旧用量。参考变化或来源参考未知时必须给出`benchmark_revision_reason`。

停止的研究运行或evaluation-only运行都可作为来源；后者从其持久队列提取发布物，不要求存在模型会话。新引擎下重新评价另有身份与新输入，旧队列成绩不搬过来。

每个发布物的断言和行为变化见证会实际重跑；缺少/损坏回归明确无效，不把历史“通过”计数当成本次通过。随后才执行新牌开发比较。

继续已有、当前引擎下的任务：

```bash
.venv/bin/bridge-evolve evolve evaluate --run .runtime/evolution/evo-<id>
```

新建的evaluation-only配置会持久冻结`evaluation_only=true`，以后普通resume也不会启动研究。对旧研究运行显式调用`evaluate --run`只改变本次执行方式，不修改其冻结配置。

此模式不创建模型客户端、不读模型凭据、不发现模型、不发推理请求，也不申请晋级或万副检查。配置中的模型名称只保留来源/兼容元数据。示例用最小合法模型预算作为防误用保护，实际应始终为0次模型请求。

展示看板增加独立候选评价表及“仅继续候选评价”按钮，入口为：

```text
POST /api/evolutions/<id>/evaluate
```

正文必须为空对象，不允许借继续评价改写冻结配置。旧引擎运行不能原地换代码续跑，应显式导入新实验。

## 5. 开发结果与晋级继续分开

评价可以得到通过、未提升、未触及改动、候选无效、比较受阻或资源不足。可分析的失败也是结论，但失败分数不参与排名。

评价队列不直接更新冠军。正常研究完成后，满足开发条件的候选仍走有限的新牌确认、原有单侧门槛和单对手保护。相同候选/父本已经获得确认结论时不因跨代重发再次自动申请；evaluation-only不执行确认。

跨运行的campaign级错误预算、Bootstrap尾部校准、完整成本/实际AI Credits统计、1NT模块合同与Local vs Global仍是后续工作，不能因这次可靠性修复而宣称已经完成。
