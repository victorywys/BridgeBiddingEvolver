核心问题是单位资源能否稳定获得完整的研究结论，而不是表达能力不足。近期不重写DSL、不扩展研究Agent数量，不因模型额度还有余量就扩大运行。

## 2. 不变的目标

- 有效候选只按规定的配对比赛成绩排名，不惩罚复杂度，不奖励新颖性。
- 运行策略只看本人手牌与公开信息。离线诊断可看授权完整牌，但不能把DDS最优定约变成强制叫牌标签。
- 每轮现场抽新牌，不预留训练/测试池；同轮共用输入，恢复保留原轮次，候选冻结先于新比较数据。
- 从零设计与全体系重构仍是长期方向；1NT只是降低首个方法实验的混杂因素。
- 失败、无提升、证据不足都是有效研究结论，不能为展示“进化”强行晋级。

## 3. R0 / P0：先修结果边界与固定参考

### 所有反馈路径必须有界

现有语义导航保留，不把整套IR重新塞回研究启动包。统一覆盖工具返回、断言失败、实际/预期值、测试摘要、consult、启动继承、自动handoff、状态和展示接口。

- 小结果给摘要；大结果保存完整不可变对象，用稳定引用、节点路径、大小和明确分页入口访问。
- 测试摘要默认只带通过/失败计数、失败测试ID、断言路径、短错误和完整结果引用；不能在异常字符串中格式化整个决策。
- 传输和交接限制检查完整模型请求，包括工具定义，不只检查历史消息。
- 老的33MB失败记录原样留档；新上下文引用它，而不是删掉原证据或静默截断成“通过”。
- 失败断言仍使测试失败。修正断言路径、压缩错误和消除程序缺陷是不同操作，不得借瘦身放宽有效性。

验收：用已有大失败形状复现，完整结果可按引用读取；下一代初始化/自动压缩后请求仍在配置上限内，实际失败数量和错误类型不变。整个验证不需要付费模型。

### 参考可靠性与研究独立

复现并修复已知参考反例，补发送/公开解释/接收方的真实行为回归。修复版本用新哈希、新版本和明确的参考修订原因，不覆盖v5.5.4，不重标旧分数。

不要求先把所有传统手册完全形式化，但已知阻塞不能继续挂着做正式排名。未知搜索超时、不成立的公开保证、候选缺陷、固定对手缺陷与DDS/基础设施错误分别记录，不补Pass、不删牌、不补0分。

验收：原失败输入完整重放及相邻边界通过；新比较配置与老参考隔离；对故意损坏的参考仍明确阻塞。

## 4. R1 / P0：一个研究单元必须获得结论

目标过程：

```text
Hypothesis -> Candidate freeze -> Validation -> Development evaluation
                                               -> Conclusion + archive
              |                                      |
              +-> 持久评测任务，不等待后续LLM会话 ------+
```

### 持久队列与调度

- 发布后立即登记评测意图，不等所有谱系或整代结束。可信程序负责状态、计费与冠军指针，不需要LLM逐个审批。
- 保存候选/父本哈希、引擎、固定对手、评分口径、阶段、同批比较集合和输入清单身份。运行标签或不同发布次数不构成新候选。
- 冻结同批候选集合后才抽共同新牌；后到者进下一批，不看过结果后插入旧批。不同批次均值不直接混排。
- 配对和时间资源单独预留。模型额度耗尽时，已承诺的评价可在其硬预算内继续；不能绕过总时间/计算上限。
- 同一评测意图恢复不重复预留/计费，不重抽牌。预算不足保留明确的等待/阻塞状态，不能丢任务或伪造成绩。
- 共享评测缓存和有界DDS进程池，保持单可信写入者或事务边界，不让各worker各自复制全局额度。

### Evaluation-only

只消费已冻结协议与评测意图，不创建研究会话、不发现模型、不发送模型请求。仍执行真实有效性检查、DDS配对、失败归因和配对/时间硬预算。

同一候选在相同环境中已有完成记录时引用原结果，不重复算作新候选；新引擎/参考或新独立确认块有明确的新评价身份。

### 开发评价不是晋级确认

开发反馈可以供后续研究阅读。申请晋级另走冻结的候选选择、新共同牌、确认次数和错误预算；发布不能自动无限获得显著性检验机会。

验收：Z发布后模拟A额度耗尽或网关失败，Z仍获得预留范围内的结论；杀进程/恢复不重复计费；evaluation-only模型调用数为0。结论可以是无提升、无效或比较阻塞。

## 5. R2 / P1：恢复既有成果并衡量研究吞吐

两个E005发布物已随Git保存，原始哈希、同源规范、案例与48/72项断言完整保留。下一步是显式迁移至修订后的评测环境，重新执行门禁和新牌评价，而不是让模型再次原样发布同一哈希。保存来源引擎/模型/父本，不复制旧分数或声称抹掉旧消耗。

每个会话、唯一候选和完整研究单元记录：

- 输入、输出、缓存读/写、未报告用量、重试与保守预留；可获得时记录上游实际AI Credits收据，缺失不能写0。
- 墙钟时间、模型等待、工具时间、DDS新求解/命中、配对尝试/完成/失败，避免把嵌套consult时间重复相加。
- 独特提案数、重复发布数、实际行为变化、有效性结果、可评分完成率和阻塞归因。
- 单位完整评价成本，以及单位有效可评分候选成本；分母为0时明确不可定义，不输出虚假的0成本。

输入/输出比不是成本结论：E006主研究输入约96%为缓存读，费用需要实际计费口径。缓存多也不能为无产出的长会话开脱，延迟、有效结果和真实费用要一起看。

会话保留独立预算与阶段性检查：是否形成可测试假设、反例、实际测试和候选结论。连续只读时允许缩小任务或有限延长，但不强制为了交差发布无意义修改，也不惩罚协议复杂度。

上述吞吐指标用于工程诊断和调度，不替代成绩适应度。先取得5–10个不同候选的完整研究记录；失败必须保留，但“有10个记录”不是方法有效性的统计证明。

## 6. R3 / P1：最小1NT模块合同

先固定自然可达的1NT入口、开叫范围、外围策略、局况与干扰约定。模块内部可重分配叫品、信息划分、问答树和退出，不设置传统规则ID白名单；修改跨接口时另立扩大范围的实验。

合同至少包括：

| 项目 | 验证 |
| --- | --- |
| 入口与角色 | 明确真实历史和可进入的手牌条件；强制前缀另标反事实 |
| 手牌域 | 可说明分母的有限抽象枚举、代表类与边界反例 |
| 发送与解释 | 同一公开叫品的保证覆盖所有可发送分支，不读私有命中 |
| 规则重叠 | 最高优先级歧义显式失败；更高规则遮蔽不能被当成已覆盖 |
| 接续与逼叫 | 接收方、所有规定答档、干扰及义务处理有可执行后续 |
| 退出 | 合法终局或明确交还外围；始终Pass不能掩盖漏分支或违约 |
| 外围兼容 | 重新执行完整牌局和共享依赖的回归 |
| 同源说明 | 从实际IR重建全部协议，不依赖隐藏权重或未定义判断 |

有限抽象/抽样不声称穷尽全部手牌。报告分别列静态检查、有限类别覆盖、自然到达和反事实边界。测试通过也不等于策略强。

验收：至少整体替换两个相互耦合分支；植入漏答、重叠、非法退出和错误公共保证时均能发现，并保留反例。

## 7. R4 / P1：Local vs Global受控Pilot

以下是待接线的方法实验，不是现有`source`或`mode`的新配置枚举。复用同一通用v2引擎、DDS和评测器；独立局部1NT运行入口尚不能直接承担统一进化实验。

| 组 | 自由度 | 用途 |
| --- | --- | --- |
| A / Fixed | 冻结传统模块和外围 | 参照，不消费研究模型预算 |
| B / Local | 相同模块起点，只允许预定义局部编辑 | Local Search |
| C / Global | 同一起点，可整体替换模块内部协议 | Global Protocol Design |
| D / Blank | 不以传统模块初始化，但保留相同入口/外围 | 后续消融，B/C跑通后再加入 |

B/C使用相同模型、工具证据、初始策略、入口、对手和评价环境；提前冻结局部编辑的操作定义，避免把一个人为弱化的B当作对照。

提前指定主要资源预算口径，同时报告token/缓存/真实费用、时间和模拟预算。不能只对齐请求数，就宣称研究资源相同。Global空间包含Local，不意味着相同预算下必然更容易搜索。

做多个独立研究重复，保存模型设置、实际响应和发牌来源。单条演化轨迹或一次正结果不能证明方法优势。

分别报告：

- Conditional IMP：候选选择前固定的入口分布；不能各自按候选策略挑牌。
- Global IMP：完整均匀发牌与冻结外围/对手下的比赛表现。
- 运行完成率、协议有效率、带明确分母的覆盖、实际结构变化、完整评价成本与不确定性。

不能把条件内收益直接外推总体收益；`入口频率 × 条件收益`只作诊断，不替代真实完整策略重测。结构新颖性用于分析，不进入奖励。

## 8. 同步研究纪律与外部基线

工程Pilot可以在明确不作论文显著性主张的情况下推进，不必等待所有统计工具完成。正式实验前需campaign级确认/目标检查台账，跨run继承已消耗的错误预算；新开目录不能重置显著性。

当前只做run内修正。默认pilot的2000次bootstrap在alpha=0.005尾部约有10个重采样结果，需预先设定并校准分位精度。继续用牌族为独立单位，多个对手共享重采样索引；不因中途普通区间好看就提前停止。

候选确定后抽新牌，不需要永久保留测试池。可分析完成的历史确认块，但未来主张必须有新的独立输入与剩余错误预算，不能用原确认数据反复修补后重测。

提前调查外部强基线的权重/规则获取、授权、运行条件、公开信息接口、对手适应和评分口径。BRL/Pidgin等名字仅是待核实候选，不承诺已经可获取或接入；端到端神经策略与可公开描述的搭档协议应区分比较。
