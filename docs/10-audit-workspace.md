# 审计工作台：人类参考、叫品频率与条件批次

## 入口与历史

运行已有本机显示器：

```bash
.venv/bin/python -B tools/board_viewer.py --port 8765
```

根页面现在是审计首页：查看冻结运行、单副/批量任务、自定义牌例库，并开启新的条件批次。带`?run=...&board=...`的历史链接仍直接进入牌例审查。顶部“首页”可返回，历史搜索只影响列表，不修改记录。

日常界面只展示手牌、叫品含义、联手信息、成绩、满贯/进局统计和真实错误。工程来源、检查计数、规则trace及数据结构放在折叠详情或报告中；不再重复展示“冻结定义”“独立最终测试”“验收未完成”等说明。95%区间数值保留，不在每个页面重复给出研究结论提示。失败牌数和未计分状态仍明确显示，不能把去除说明文案变成隐藏错误。

### 整理、分类与回收站

首页“审计记录”统一列出历史运行和已结束/正在执行的任务：

- “整理”可修改显示名称，填写任意分类；名称及分类与原审计输入、报告和文件哈希分开保存。
- 可按名称、原名称、分类搜索，按分类和任务状态筛选；分类为空表示“未分类”。
- 复选框支持全选当前筛选结果、批量分类及批量删除。切换筛选时不会保留看不见的选择。
- 删除前列出所选记录并要求确认，实际是移入**回收站**；首页、运行选择器和最近任务中随即隐藏。回收站可单条/批量恢复，刷新页面或重启服务后仍有效。
- 正在运行或排队的任务不能删除；可先取消。未知记录、混合了无效ID或活动任务的批量请求整体拒绝，不执行一半。

整理元数据保存在`.runtime/board-viewer/library.json`。删除不会物理清除报告、牌例、冻结体系或人类参考，也不会腾出这些文件的磁盘空间；恢复后原记录继续可用。没有自动清理用户已有的测试审计。

新批次默认按数字版本选择最新CCBA/精确体系，而不是按含中文说明的显示名称排序；也可以显式选择历史版本。历史版本的协议缺陷会如实记录为相应牌例失败，继续审计后续牌例，不冒用最新版本来替换其结果。

首页及历史任务中的“查看进度”会立即打开独立的任务窗口，不依赖当前是否处在牌例审查页。已结束任务显示“任务详情”。窗口展示阶段、进度、采样/接受/已审计数量、有效配对与失败数量、实际种子及报告入口；关闭窗口不会取消任务。旧任务缺少的计数显示“未记录”，不补写历史证据。

“打开牌例与检查详情”会立即进入审查页，显示加载进度和已用时间，不再把“载入中”藏在首页背后。加载期间同一请求不会重复提交；“返回首页”只取消本次打开，不取消或改写已经完成的审计，迟到的响应也不会覆盖新页面。打开失败会持续显示具体错误，支持“重试打开”，不会只闪过一个提示。

### 加载方式与耗时

界面先请求**轻量整批索引**，包含全部手牌/牌型摘要、两桌叫牌序列、定约/得分、满贯筛选标记和搜索文本，不附18,000多叫的完整公开状态与私有trace。列表和统计出现后，仅请求当前选中的一副详情；翻牌按需读取，客户端最多缓存32副。全批频率仍使用完整1000副的全部实际叫品，不随筛选或已读取详情的数量变小。规则ID及已保存中文含义仍可搜索。

界面创建的审计首次打开时，服务校验报告和证据、顺序扫描JSONL建立字节位置索引；之后按位置读取单副。服务缓存最近两份轻量索引，每次请求仍核对原文件哈希，详情另核对单行身份；报告版本变化会使旧请求失效。冻结历史运行沿用原来的完整一致性校验，再生成轻量界面数据。普通导入仍重建公开说明，不冒用审计保存内容。

完整JSON/PBN导出由服务端读取所选牌例的完整记录，**不把轻量索引当作完整审计导出**；保留公开信息、私有trace、DDS及审查备注。另可导出“无损压缩记录”或“Agent摘要”：前者能完整导入，后者仅供分析且不能冒充完整记录。旧的完整运行API继续可用。

以1000副、18,502次叫牌的同一记录实测：旧接口首开生成响应约8.97秒，返回145MB JSON（gzip约11.4MB），还需解压与解析；轻量索引约5.01MB（gzip约606KB），首次建立约2.94秒、缓存后约0.11秒，选中一副详情约0.11秒。真实浏览器首屏2.998秒、完整选中详情3.113秒。首次剩余开销主要是扫描原始大文件并建索引；再次打开不重复扫描。这些是本机测量，端口转发和网络仍会影响实际体验。

服务仍仅监听远端`127.0.0.1:8765`；VS Code端口转发的本地端口可能不同，以实际转发地址为准。没有取消原有来源限制，所有新接口沿用本机/显式可信来源保护。

## 体系进化实时追踪

首页“体系自进化”的“实时追踪”和历史库“迭代追踪”进入同一个进化看板。可收藏`/?evolution=<实验ID>`；重新打开会直接回到该实验。关闭页面、看板或浏览器不取消独立启动的后台进化，只有“安全停止”才写入取消请求，在模型/工具/DDS安全边界生效。

看板约每2秒读取已持久化检查点，不额外调用模型：

- **实时总览**：当前代数、模型等待/工具执行/DDS评测阶段、步骤已用时间、配对完成数、请求/token/时间预算、当前研究草稿及实际测试状态。
- **重要里程碑**：研究假设、体系编辑、真实测试/探索结果、独立讨论、发布及晋级；不是重复展示每次查文档。全部里程碑支持分页和跟踪最新记录，并能打开对应研究的实际prompt及工具输入/输出。
- **迭代与成绩**：选择一个已完成轮次，用图表和表格对照同一批牌的各版本成绩。研究探索单独标明；无效或缺失分数显示“—”，不能变成零分。晋级提升及单侧下界与对原对手的绝对均值分开显示。
- **当前体系**：每条谱系的已冻结冠军、内容哈希、规则/状态数量、最近评测、来源和晋级信息；可直接阅读完整说明或IR、下载原文件。研究草稿与已发布冠军分开，不因草稿变化就替换冠军。
- **完整记录**：每代候选、研究会话、原始提交及分片审计牌例；所有旧入口保留。

轮询断线会明确显示“显示上次记录”并自动重试；不会清空已读成绩，也不会在重连时丢掉当前页签、比较轮次或展开的详情。后台恢复仍核对配置、引擎和冻结输入，预算不重置。

已发布实验可通过“从当前冠军继续新实验”继承实际冠军及其回归案例，不退回全Pass空白父本。过去相对旧父本的行为变化测试会转成新父本的普通回归，新候选仍须提供新的行为变化见证。未发布草稿继续使用原有“承接未发布工作”入口。新实验预算需明确确认，旧成绩和用量不复制、不清零。

固定对手自己出现协议检查错误时，看板显示“**研究继续，正式比较受阻**”，保留原始问题牌和对手身份。研究Agent可继续设计、调试、发布候选，但不能把失败的对手当作获胜，也不会确认正式晋级或万副达标。DDS、存储等基础设施异常仍暂停/失败，不以“研究继续”掩盖。

相关接口：

```text
GET /api/evolutions/<id>
GET /api/evolutions/<id>/timeline?offset=0&limit=50
GET /api/evolutions/<id>/research/<session>
GET /api/evolutions/<id>/systems/<hash>.md
GET /api/evolutions/<id>/systems/<hash>.json
```

### 修改进化界面

页面源码入口为`tools/board-viewer/app.entry.mjs`；`app.mjs`是提交并实际提供给浏览器的构建产物。新增的进化模块统一打包，仍通过既有静态路由加载，避免为了改界面而修改正在执行中的可信评测源码。

```bash
npm --prefix tools/board-viewer ci
npm --prefix tools/board-viewer run build
npm --prefix tools/board-viewer test
```

更新前端后重新构建、刷新页面即可；不要手改生成的`app.mjs`。修改Python评测代码或两个可信工具文件会改变引擎身份，不能在进化运行期间这样做并混用旧成绩。

## 人类参考叫牌

在每副“叫牌对照”下打开“编辑/保存参考”：

- 选择参考对应的第一/第二桌，可以复制该桌系统序列后修改，也可以从空序列手工填写。
- 从发牌人开始，按顺时针输入四家叫品。支持`P`/`Pass`、`X`、`XX`、`1C`至`7NT`、花色符号，以及`AP`补齐剩余Pass。
- “检查并预览”只检查桥牌合法性、行动顺序、叫牌结束和真实庄家；不要求服从系统的逼叫或私有策略。这是人类建议，不是强行重算系统的结果。
- 可以保存完整序列，也可以保存合法的部分前缀。部分前缀有明确的下一行动位置，最终定约为`null`，不补Pass或零分。
- 填写名称和建议理由，保存时创建新版本。旧版本保留，可以载入为新草稿，不做破坏性覆盖。

参考按**完整四手牌＋发牌人＋局况**关联，所以同一副重跑后仍能找到；版本槽同时记录桌次及双方体系哈希，避免把不同协议的建议当成同一标准。历史载入只是复制草稿，重新保存会绑定当前选择的桌次和体系。

服务端保存在`.runtime/board-viewer/human/<手牌身份>/human-<唯一ID>.json`，不写入冻结`results/`或浏览器本机备注。每条包含：

- 规范化手牌、发牌人/局况、完整或部分公开叫牌、终局定约或`null`。
- 原运行/副号定位、桌次、双方体系身份、版本号、前版本ID、保存时间。
- 人类建议名称和理由、内容哈希、`human-post-hoc-reference`范围标记。

“导出全部参考JSONL”导出全部历史版本，供后续离线优化/评测标准读取；其中没有系统私有命中trace。它是独立的人类参考schema，不与系统审查JSON或PBN混合。普通“导入牌例”会明确拒绝把此JSONL当作系统审计导入，避免悄悄把人类答案混成策略输出；备份工作目录可以完整恢复服务器上的参考版本。

**信息隔离**：当前策略运行器、公开叫品解释、批次发牌器和叫品频率均不读取人类参考。后续若要用作优化目标，必须另行显式加载，并说明使用的是开发数据，而不是未见过的人类保留测试。

## 点击叫品后的全批次频率

统计按当前载入的**整批记录**预建索引，不随左侧牌型/定约/个人标记筛选缩小。对第k个叫品，使用从开局到第k−1叫的**完整前缀**，包含全部Pass、X和XX；后续叫牌、真实手牌、私有规则ID和DDS都不是匹配条件。

默认“严格局面”还要求：

- 双方体系哈希及NS/EW布局相同；
- 发牌人、局况相同，因此当前位置/行动者也相同。

“同体系序列”按相对发牌人的双方体系及完整前缀匹配，忽略绝对座位和局况。它适合查看更广的序列覆盖，但不能冒称完全相同的决策条件。缺少体系身份的导入记录会明确提示。

页面同时显示：

1. **出现次数**：具有该完整前缀并选择当前叫品的桌次数，以及涉及的不同牌例数。
2. **当前局面选择率**：上述桌次数÷在相同条件下实际记录了下一叫的桌次数。未记录下一叫的部分前缀不被当作Pass或一次拒绝。
3. **占全批牌例比例**：涉及该序列的不同牌例数÷全批基础牌例记录数；同一副两桌都出现，只算一副。
4. **占全批桌次比例**：上述次数÷全批表记录数，另行标明分母。

同时列出相同局面下其他实际叫品的选择次数。人类参考不计入这些数值；交互重叫只在原批次里查找相同前缀，没有匹配机会时显示“—”，不会凭当前重叫制造一次频率。失败牌仍在全批牌例分母中，但仅统计实际返回的叫品；没有轨迹的失败桌不产生虚构的Pass或决策机会。频率表示出现情况，不表示叫品已通过审计。

## 条件随机发牌与新批次

首页可设置：

- 1–1000副基础牌例、可选整数种子、A/B体系；
- 固定或循环发牌人，固定或既定周期的局况；
- N/E/S/W每家的HCP及S/H/D/C张数上下界，所有条件同时成立，留空表示不限；
- 最多尝试发牌次数，默认`max(10000, 牌数×1000)`，最高100万次。
- 审计进程数：自动或手动1/2/4；API接受1–4的整数，实际不超过牌数。自动模式不足64副用1进程，64副起最多2进程（不超过报告的CPU数量），避免小批次启动多个大体系解释器反而更慢。

先检查区间、每家13张、全副40 HCP和每花色13张的必要可行条件；复杂稀有组合仍须实际采样，不保证边界检查通过就一定能够生成。

种子留空时，在正式提交时用系统随机源生成一个`0..2**53-1`整数，并固定保存到任务、输入和报告；手工填写`0`仍是有效的固定种子，不会被替换。条件预检不提前生成一个与实际提交无关的种子。API允许省略、`null`或空白字符串；非空值仍须是范围内的整数，布尔值、小数和数字字符串会明确拒绝。按原输入重跑会复用已记录的实际种子。

发牌使用独立`random.Random(seed)`对标准52张牌完整均匀洗牌，然后按全部条件**拒绝采样**，仅接受不同基础牌族，不通过移动牌张来凑数。固定种子及条件可复现相同的牌；同一种子重复提交的新任务**不等于新的独立样本**。当前只去重本批牌族，不声称已检查与全部历史数据的重叠。

任务仍依次排队，最多8项执行/排队任务；一个批次内部可按牌例并行。页面显示尝试次数、接受副数、已审计副数、实际进程数和阶段；关闭页面不会取消任务。取消会停止补交任务并取消尚未开始的工作，已经进入原生DDS的调用会等待返回并释放资源，不强行中断原生库。服务重启则将未完成任务如实标成中断，可按原条件创建新任务，不能把未完成数据拼成成功批次。

每副采用相同四手牌、发牌人和局况做两桌换位，保存策略原始输出；真实DDS给出墩数和dealer par，默认前5副还绕过缓存重新求解。每副检查合法性、确定性、已编码公共/私有区间及已登记的人工终局模式。**本入口没有运行完整体系语义契约，检查数明确为0，不冒称全面验收。**

### 并行执行与信息边界

- 整副叫牌使用逐叫增量公开状态，独立单手决策仍从自己的不可变观察重建状态；详见[v2调度](08-general-protocols-v2.md#3-通用调度与前缀)。
- 即使只选1进程，也会先启动独立DDS线程，再在叫牌线程运行两桌和公开说明。固定DDS通过`ctypes.CDLL`调用原生C函数，调用期间释放GIL，因此可以与Python叫牌计算重叠；不是把两段Python CPU循环换成线程后宣称多核加速。
- 多进程使用`spawn`，不继承已初始化DDS的线程/锁；每个工作进程独立加载本任务的冻结体系并核对内容身份。每进程的原生DDS仍为单worker、进程内串行调用，允许不同进程各自求解。
- 在途工作不超过进程数的两倍。子进程完成顺序可以不同，主进程仍按输入副号保存记录、错误和统计；随机发牌和种子只由主调度端处理，并行顺序不改变牌例或策略观察。
- **两桌完整确定性复跑、前5副新鲜DDS交叉核验、公开/私有边界检查全部保留**，没有改成抽查或“快速但不完整”的审计。
- DDS缓存按实际求解器来源与精确座位牌例键共享。并发相同求解允许一致结果重复提交，但会校验已存表与新鲜结果一致；冲突不能靠忽略写入掩盖。
- 进程初始化失败、子进程崩溃及保存错误仍使任务失败，不伪装成某副通过。普通逐副策略/检查失败仍留在该副并继续。

DDS及其线程完成状态、工作进程身份、种子和其他牌例结果不进入`Observation`或公开协议。进程数只是调度配置，不改变叫牌含义或评分。

### 本次性能与等价验证（2026-11-03）

完整Python回归436项在强制真实DDS模式下通过，另有22项前端统计/筛选测试。真实浏览器验证了进程选择、双进程任务、报告、DDS及390px布局。详细数据见[验证记录](../results/audit-performance-validation/validation.json)。

| 20副，DDS未命中缓存 | 30.01秒 | 14.31秒 | 13.49秒 |
| 同20副，DDS命中缓存 | 21.48秒 | 8.04秒 | 10.47秒 |

旧实现计时来自此前同牌测量，不是同一时刻的独占机器对照。小批次命中缓存时，额外进程的体系加载成本可能超过收益，因此自动模式采用64副门槛。另一组128副、两次均128次DDS缓存命中且保留5次新鲜核验的受控比较为：优化后单进程52.97秒、双进程33.00秒，约1.61倍；结果完全一致。

另以原1000副的同种子、同条件和同冻结体系创建新任务`audit-5f923635801b413da7eec11a7c2e19f8`，双进程严格复验用时228.35秒。全部2000桌、18,502次叫牌的逐叫与终局记录、DDS/par、区间检查、IMP、满贯/进局汇总均与原任务相同；只新增缓存核验计数等执行元数据，原文件哈希不变。这次1000次DDS缓存命中、0次缓存未命中新求解，另有5次绕过缓存交叉核验，**不能把它与旧批次约23.5分钟的差值全部归因于引擎优化**。本次是运行等价与工程性能验证，不是新的体系强度结论。

策略/协议错误、区间不实、单副DDS/Par或审计检查失败，都记到**该副**并继续后续牌例。单桌叫牌失败时仍尝试另一桌；保留成功返回的轨迹和已核验的DDS诊断。若执行器在抛错前未返回轨迹，明确标注“未返回”，不补造历史或Pass。

全部请求牌例处理完毕后，任务状态是`completed`，有失败时报告为`completed-with-findings`、机械检查为`failed`，不等于审计通过。整批仍进入可浏览目录：页首列出数量和逐副原因，可点击定位或“只看失败牌”；牌例列表有失败标记，牌内显示阶段、桌次和异常/检查原因。

失败牌不删除、不替换、不补零分；其配对IMP和分差保持`null`，即使保留了两桌原始诊断分数，重载或导入也不会重新生成有效IMP。成绩、进局和满贯汇总仅覆盖**有效配对子集**，明确展示纳入/排除数量，不作为含失败完整批次的公平比较；没有有效配对时不生成总分、均分或置信区间。

条件采样耗尽、冻结配置/源码变化或保存故障仍是任务级失败，取消和服务中断也分别保留真实状态，不能用逐副容错掩盖。未处理完的批次不冒充完整运行。接受的输入及可保存的错误证据保留，不放宽条件。生成分布已被用户条件选择，因此所有成绩仍仅为开发诊断，不作独立强度排名。

### 批次保存和下载

每个任务保存在`.runtime/board-viewer/audits/audit-<唯一ID>/`：

- `input.json`：固定条件、种子、牌数、体系身份与请求哈希。
- `systems/<哈希>.json`：实际选择的冻结体系。
- `dataset-boards.jsonl`：实际接受的规范化完整手牌与牌族身份。
- `boards.bridge.jsonl`：全部牌例，包括失败牌；实际返回的两桌逐叫、公共解释/私有trace、可用的真实得分/DDS/par，以及`audit_result`逐副状态、检查、错误和`dds_verification`缓存/新鲜核验信息。失败桌另有`error`。
- `audit-report.json` / `report.md`：结果、逐副失败汇总或任务级错误/取消原因，有效配对子集的满贯/进局统计、检查数和证据身份；`execution`记录进程数、DDS线程重叠及在途上限，`metrics`分别统计DDS缓存命中、新求解、新鲜交叉核验和未取得缓存计数的牌数，不能把缓存命中的加速全算作引擎优化。
- `job.json`：实际种子、审计进程数、进度、已处理/有效/失败副数、状态与报告哈希。

可下载中文报告、机器报告或完整ZIP，ZIP包括上述JSONL文件。再次打开或下载核对文件哈希；已完成的条件批次自动进入首页和运行选择器，不用重启服务。原实验记录和既有人类参考不覆盖。

新任务的文件名保持兼容，但记录本身使用版本化紧凑格式：批次`boards.bridge.jsonl`为`bridge-record-log/v2`，单副`board.bridge.json`为`bridge-record/v2`。报告的`records`记录格式、实际／展开大小、条数及字典项数量；正式评测的`boards.jsonl`与`auctions.jsonl`同样支持紧凑记录。不要直接把紧凑行的数组当作完整牌例dict，使用共享读取器或`records`命令。详见[格式及Agent读取](11-compact-records.md)。

审查JSON保留逐副/逐桌错误；PBN用扩展标签`ReviewAuditResult`和`ReviewExecutionError`保存相同诊断，空轨迹的失败桌也能往返导入。其他PBN软件可能忽略这些扩展标签，因此完整证据备份仍以JSON/ZIP为准。
