# 代码 workspace 的启动提示词

将以下正文整体粘贴到目标代码仓库的编码助手对话中。

---

请在当前仓库实现 Bridge Bidding Evolution：一个能够通过同牌实验、自动变异、种群筛选持续改进桥牌叫牌体系的平台。请直接检查仓库并开始编码，不要只返回方案。

先读取仓库已有的 AGENTS.md 和本项目文档：

- docs/01-research-brief.md
- docs/02-architecture.md
- docs/03-system-language.md
- docs/04-evaluation.md
- docs/05-roadmap.md
- docs/06-experiments.md

研究目标已经确定：第一阶段只按成绩摸高，不对体系复杂度、长度、记忆难度或非传统含义施加任何惩罚。体系须可执行，且完整自然语言说明足以让独立实现者重建同一决策协议。套质量、控制、大牌组合、多轮接力、转移和问叫都在允许范围内。

当前目标是完成 M0–M5 的最小可信局部闭环，已完成的里程碑先验证，不要重建：

1. 检查真实开发环境，建立适合现有仓库的 Python 包和 CLI。
2. 实现桥牌叫牌合法性、终局定约/庄家、计分和带符号 IMP。
3. 实现可扩展规则 IR、协议解释器、自然语言规范生成及完整初始 1NT 后续协议。
4. 接入真实 DDS，生成小规模可复现数据和缓存；完成受限观察与信息隔离。
5. 跑通 uncontested-1nt 同牌比较、逐牌记录和统计报告。
6. 实现不依赖 LLM 的变异、校验、top-k、独立确认和历史归档，自动跑至少一次小规模多代实验。

按里程碑实现和验证，再继续下一阶段。完整竞争基准和四人竞争两桌评测随后单独交付，不能因缺少完整四位置策略而阻塞局部进化。初版无需前端、分布式、神经网络或 LLM API。先从一个子协议切入，不代表最终只研究 1NT；核心叫牌引擎需要支持完整合法动作空间。

请特别执行以下约束：

- 决策只接收自己的牌和公开信息，不传入完整 Board、DDS、par、数据行号或种子。
- 搭档按同一体系版本执行；修改含义时同步修改理解与后续。
- 根据真实庄位查询 DDS，计分统一南北视角；每副先转换 IMP，再取平均。
- 四人竞争中，A NS/B EW 与 B NS/A EW 使用同一 Board，A 的分差为 S1_NS-S2_NS。两桌合成一个样本。
- uncontested-1nt 是固定开叫前缀和对手 Pass 的局部比较，不能冒称完整竞争成绩。
- 保持训练、筛选、独立确认和最终测试隔离。同牌的局况或座位旋转变体不能跨 split。
- 非法动作、规则冲突和失败牌例不能静默修正或剔除。
- 没有真实 DDS 时明确保留未完成状态；fixture 只用于测试。继续完成不依赖它的部分，不伪造研究结果。
- 不把距全知最佳定约的差值当成每次叫牌的正确性标签。
- 所有成绩只支持对应实验设置，不宣称找到桥牌最优体系。

文档中的结构是初稿，遇到实际 API 或工程冲突时可以调整默认实现，但请记录修改理由，不改动已确认的研究目标。日常可逆决策自行推进，无需逐项确认。

优先运行对核心正确性有意义的测试：叫牌状态/加倍边界、庄家、计分与 IMP 分段、IR 优先级和协议、信息不可见性、配对符号与可复现性。不要只做文件存在性测试。

最终请交付：实际代码、可运行命令、初始体系 JSON 与对应完整中文说明、最小实验配置、实际实验报告和后续待办。报告中清楚列出已完成里程碑、实际运行的检查、DDS 的真实接入状态和未完成事项。若本轮没发现更高分体系，如实保留 incumbent 并说明结果。
